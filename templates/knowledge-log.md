# Project Knowledge Log

This file records substantive project milestones in reverse-chronological order, newest first. Stable conclusions belong in `knowledge/topics/`, not here.

Create the file only on the first durable conclusion or when the user explicitly requests a persistent timeline. A multi-session project alone is not a trigger.

Do not log every task transition, routine status update, repeated checkpoint or unchanged evidence refresh. Keep each entry short (about 20 non-empty lines or fewer): summary and pointer only.

## YYYY-MM-DD · <short title>

- What changed, was decided, or was learned.
- Evidence / artifact / receipt pointer.
- Affected task or topic pointer.
